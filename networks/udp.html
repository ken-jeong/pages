패킷 시간선

시간 ↓ · 실선: 데이터 / 제어 · 점선: ACK · ×: 손실

도착 이벤트를 한 단계로 묶은 학습 모형입니다. 간격과 기울기는 실제 지연을 나타내지 않습니다.

현재 단계

송신 측 / 클라이언트
수신 측 / 서버
수신 앱에 전달한 데이터

    UDP에서 기억할 것

    메시지 경계를 유지합니다

    각 데이터그램은 별개 메시지입니다. 이 모형은 수신 버퍼가 충분하고 데이터그램이 잘리지 않는다고 가정합니다.

    전달과 순서를 보장하지 않습니다

    손실·중복·순서 변경이 생길 수 있습니다. ACK, 재전송, 순서 복원이 필요하면 상위 프로토콜이나 앱이 구현합니다.

    작은 전송 계층 헤더

    UDP 헤더는 8바이트이며 출발지·목적지 포트, 길이, 체크섬으로 구성됩니다. 연결 수립이 없다고 항상 더 빠른 것은 아닙니다.

    A·B·C는 앱이 붙인 메시지 이름이며 UDP 헤더의 순서 번호가 아닙니다. 전송 시도만으로 송신 앱이 상대의 수신 여부를 알 수는 없습니다. 체크섬은 손상 검출에 쓰이며 손실 복구 기능은 아닙니다.

    참고: IETF · RFC 768 · UDP · RDT · ARQ
