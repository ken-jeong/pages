pthread_cond
조건 대기 · 신호 · 뮤텍스 재획득

소비자는 items > 0을 기다립니다. 생산자 P는 뮤텍스를 잠그고 항목을 추가합니다. 신호를 보낸 뒤 잠금을 해제해보세요.
뮤텍스 소유 스레드
조건 변수 대기 / pthread_cond_wait
뮤텍스 획득 대기 / 깨어난 스레드도 여기서 대기
소비 완료

CONDITION VARIABLE

<pthread.h> · pthread_cond_t + pthread_mutex_t
  • 체험 순서: 소비자 추가 → 조건 검사(wait) → 생산자 잠금 → signal → mutex_unlock → 조건 재검사(소비)
  • wait는 잠근 뮤텍스를 원자적으로 해제하고 대기합니다. 반환할 때는 같은 뮤텍스를 다시 소유합니다.
  • signal은 대기 스레드를 적어도 하나, broadcast는 모두 깨웁니다. 이 예제의 signal은 하나를 선택합니다.
  • 신호는 저장되지 않습니다. 대기자가 없을 때 보낸 신호는 미래의 wait를 통과시키지 않습니다.
  • 허위 깨움이나 다른 소비자의 선행 소비에 대비해 while로 조건을 다시 검사합니다. 깨움 자체는 items를 늘리지 않습니다.
  • 이 예제는 대기 순서를 FIFO로 표시합니다. 실제 깨움·뮤텍스 획득 순서는 보장되지 않습니다.
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
int items = 0;  /* 모든 접근은 mutex로 보호 */

/* 소비자 */
pthread_mutex_lock(&mutex);
while (items == 0)
    pthread_cond_wait(&cond, &mutex);
items--;
pthread_mutex_unlock(&mutex);

/* 생산자 */
pthread_mutex_lock(&mutex);
items++;
pthread_cond_signal(&cond);
pthread_mutex_unlock(&mutex);

/* 모든 스레드의 사용이 끝난 뒤 */
pthread_cond_destroy(&cond);
pthread_mutex_destroy(&mutex);

호출 흐름을 보여주는 예제입니다. 실제 C 코드에서는 반환값을 검사하세요. 생산자는 한 번에 P 하나만 표시하며, 잠금 중 재요청은 상태 안내로 처리합니다.
